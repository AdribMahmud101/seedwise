# NETAREA1 Implementation Plan

**Goal:** Make planner counts, season defaults, and interactive 3D zones follow the field's saved widths.

**Architecture:** Keep `netarea.js` authoritative for cultivable percentage and existing `capacity` authoritative for counts. Reuse planner instancing, DEM sampling, and animation. Zone geometry describes the requested perimeter bund, lowest-edge drain, crossing path, and corner patch; display enlargement remains explicit.

**Scope:** Existing draft in fields, netarea, journey, planner controls, planner, plan preview, planner 3D helpers/rendering, CSS, and focused tests. Preserve unrelated worktree changes. No dependencies, lockfile changes, deployment, or secrets.

## Review focus

- Width edits must update field-following seasons without overwriting overrides.

- Tiny/zero widths and concave/rotated outlines must remain bounded and clickable.
- Mobile popovers and chips must fit without page overflow or console errors.

## Evidence

Baseline: 456 tests passed; requested no-undef check passed. Existing draft had an unconditional decorative paddy bund, a continuous ground surface beneath drains, inferred rather than persisted override source, and width changes that did not update existing seasons.

Independent review found clockwise bund winding, a missing path when a concave field's centroid lies outside, a degenerate corner-patch direction, and plant jitter crossing zones. Each finding has been fixed. Renderer verification checks real mesh normals, channel depth, final plant footprints, ray picking, zero-width meshes, source labels, and water animation.

Ruling: Preserve the existing `netarea.js` perimeter deduction formula. Counts use that conservative estimate; the 3D drain occupies the requested lowest edge and the path crosses the long axis. Popover areas describe those drawn zones, so their sum is not a replacement for the cultivable-area estimate.

Final proof: 464 unit tests passed; requested no-undef command passed on all eleven changed legacy modules; production build passed. Chrome 158 passed desktop 1366×768 and phone 412×915 at 2.625 DPR with zero console errors. Actual renderer checks found 420/420 upward bund normals, a 0.3 m channel, zero root/footprint leaks, no zero-width feature meshes, successful ray picking, correct truth labels, and animated drain water. Screenshots and machine-readable results are in `docs/reports/netarea1/`.
