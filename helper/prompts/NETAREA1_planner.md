# NETAREA1 · Planner uses the field's bunds/drains/paths: counts + realistic 3D zones (click → parameters)
Source of truth: `src/legacy/netarea.js` (per-field inputs bundWidthM, drainWidthM, pathWidthM, otherDecimals → cultivable/net area; edited in the My field dialog "Cultivable area after bunds & drains", read its exported API). Owner: "make sure they are detailed and realistic; when clicked it should show parameters; make this fast". Mobile first. Keep truth labels: widths are "Entered by farmer" if the farmer saved values, else "Scenario default".
1. **One usable-area truth**: the planner's "Usable area %" slider (src/legacy/planner.js / planner-controls.js, state.planner.usable, per-season settings in journey.js) defaults to the field's cultivable share from netarea.js (e.g. 88.7 %), with a note "From your field widths · Edit on My field". If the user moves the slider it becomes "Your planner override" with a "Use field widths" reset. Counts/seed recompute from it (existing count function). Season defaults in the journey use it too.
2. **Planner 3D (src/legacy/planner3d.js + helpers)** draws the real geometry from the widths, at true scale relative to the field outline (and visibly — enlarge display if a 0.4 m feature would be sub-pixel, with the existing honest "enlarged for readability" note):
   - **Bund**: raised earthen ridge along the whole outline, width = bundWidthM, ~0.25–0.3 m tall, rounded profile, compacted-soil texture/colour darker than the field, slight grass tufts on top.
   - **Drain**: a channel along the field's lowest edge (use the DEM/elevation already available in planner/studio data; fall back to the longest edge) of width drainWidthM, ~0.3 m deep, with a thin animated water surface (subtle), muddy banks.
   - **Path**: a compacted walking strip (pathWidthM) crossing the field along the long axis, lighter worn-soil texture, slight footprint noise.
   - **Other non-cultivable** (otherDecimals): a hatched/grass patch in a corner of matching area.
   - **Plants/rows are excluded from all these zones** (update plannerRowLayout / instancing), so drawn rows match the reduced count.
   - Zero-width features are not drawn.
   - **Click/tap a feature → popover with parameters**: name, width (m), length (m), area (m² and decimals), share of field (%), source label ("Entered by farmer" / "Scenario default"), and an "Edit on My field" link. Hover highlight on desktop; tap on phone; Esc/outside closes. Also a small legend chip row "Bund 0.4 m · Drain 0.1 m · Path 0.5 m" that highlights the feature when tapped.
3. Smooth transitions when widths/usable change (reuse planner3d tween style).
